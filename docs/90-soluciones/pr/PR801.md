# PR801 — Escalar y observar

!!! note "Qué es esto"
    Guía de apoyo al lab. No sustituye el enunciado ni la rúbrica del [Tema 8](../../08-escalado-monitoreo-cierre/tema8.md#pr801-escalar-y-observar).
    Entrega: [Cómo entregar](../../index.md#entrega) → `PR801.md` (o ZIP + img/).

## Antes de empezar

- Lab Academy **M10**.
- Docs: [Create an Application Load Balancer](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/create-application-load-balancer.html), [Create an Auto Scaling group](https://docs.aws.amazon.com/autoscaling/ec2/userguide/create-asg.html), [Create a CloudWatch alarm](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/ConsoleAlarms.html).
- Durante el lab: ASG con **min ≥ 1** (según enunciado).
- Al acabar: **min = 0** o *terminate* — si no, facturas.
- La alarma debe ser de **EC2 / ALB / TargetGroup** (CPU o *UnHealthyHostCount*), **no** logs de una función Lambda.

## Recorrido orientativo

1. **Target group.** En **EC2** → **Target Groups**, crea o usa el del lab (protocolo/puerto del health check, p. ej. HTTP `/` o `/health`). Registra las instancias.

2. **Create Application Load Balancer.** **Load Balancers** → **Create** → **Application Load Balancer**. Elige subnets en **al menos dos AZ** si el lab lo pide; asocia el listener (80/443) al target group. Deberías ver el ALB *Active*.

3. **Destino sano.** En el target group → **Targets**: al menos un destino **healthy**. Captura ese estado (es el criterio ALB).

4. **Auto Scaling group.** Crea/ajusta el ASG del lab: **min**, **desired**, **max** coherentes (min ≥ 1 mientras pruebas). Vincula al mismo target group / plantilla de lanzamiento del enunciado.

5. **Alarma CloudWatch.** **CloudWatch** → **Alarms** → **Create alarm**. Métrica de **EC2** (p. ej. `CPUUtilization`) o del **ALB/TargetGroup** (`UnHealthyHostCount` / *HealthyHostCount`). **No** elijas un *log group* de Lambda como evidencia de este IE. Deberías ver la alarma *OK* o *In alarm* según el umbral.

6. **Relato corto en el `.md`.** ALB reparte a destinos sanos; ASG mantiene capacidad; la alarma te avisa. Una captura de alarma o métrica basta.

7. **Limpieza operativa.** Baja **min** (y desired) a **0** o *terminate* instancias. Captura el ASG/instancias al final.

8. **Teardown del lab.** Borra ALB, target groups, ASG, alarmas según el orden del lab. **End Lab**.

Si el health check apunta a una ruta que no existe, el target quedará *unhealthy* y el ASG puede sustituir instancias sin arreglar la app: mira la ruta del check antes de «subir el min». CloudWatch y CloudTrail no son intercambiables: aquí quieres **métrica/alarma**, no el historial de llamadas a la API. Al cerrar, un ASG con min=2 olvidado es la forma más típica de llevarse un susto en la factura del learner.

## Evidencia ↔ rúbrica

| Criterio | Qué dejar en el `.md` |
| --- | --- |
| ALB | Captura target group con destino **healthy** |
| ASG | min/desired/max anotados durante el lab |
| CloudWatch | Alarma o métrica EC2/ALB/TG (no logs Lambda) |
| Limpieza | min=0 o terminate + constancia final |

## Errores frecuentes

- Health check inútil (todo *healthy* con app caída).
- ASG con min=2 y olvidar bajarlo.
- Mirar CPU en **CloudTrail**.
- Pegar logs de Lambda como «observabilidad» de este IE.
- Diagrama sin captura de destino sano / alarma.

## Limpieza

ASG **min = 0** o *terminate*; borra ALB, TG, alarmas según lab. Comprueba que no queda capacidad ociosa. **End Lab**.
