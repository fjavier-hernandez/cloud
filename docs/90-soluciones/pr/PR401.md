# PR401 — Lanzar y comparar cómputo

!!! note "Qué es esto"
    Guía de apoyo al lab. No sustituye el enunciado ni la rúbrica del [Tema 4](../../04-computo-serverless/tema4.md#pr401-lanzar-y-comparar-computo).
    Entrega: [Cómo entregar](../../index.md#entrega) → `PR401.md` (o ZIP + img/).

## Antes de empezar

- Lab **Academy M6** (EC2 / AMI) según enunciado.
- Región y AMI del lab; tipo de instancia **pequeño**.
- Security group **mínimo** (solo lo que pide el ejercicio).
- **No** dejes la instancia encendida el fin de semana: factura.
- La comparación con **Lambda** pesa en la rúbrica aunque el lab solo lance EC2.
- Docs: [Get started with Amazon EC2](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/EC2_GetStarted.html), [Create a Lambda function](https://docs.aws.amazon.com/lambda/latest/dg/getting-started.html) (contraste).

## Recorrido orientativo

1. **Abre EC2 en la región del lab.** Consola → **EC2**. Comprueba región (esquina superior). Anótala en el `.md`.

2. **Launch instance.** **Instances** → **Launch instances** (o el flujo *Get started* del lab). Elige la **AMI** del enunciado / lab Academy.

3. **Tipo y red mínimos.** Tipo **pequeño** (p. ej. familia `t2`/`t3` micro según lab). VPC/subnet del lab. **Security group** solo con el puerto que pida el ejercicio (no `0.0.0.0/0` en admin «por si acaso»).

4. **Key pair / acceso.** Si el lab pide key pair, créala o usa la del lab; **no** pegues el `.pem` en el `.md`. Lanza la instancia.

5. **Evidencia running.** Espera estado **running**. Captura la fila de la instancia (ID / estado / tipo) o el resumen del launch. Eso cubre «Lab EC2/AMI».

6. **AMI opcional.** Si el lab pide crear una AMI desde la instancia: **Actions** → *Image and templates* → *Create image*. Anota para qué sirve (clonar sin reinstalar). Si no lo pide, no inventes un pipeline.

7. **Bloque comparación EC2 ↔ Lambda (obligatorio en el `.md`).** Con el **mismo workload mental** (p. ej. API HTTP o job corto), rellena una mini-tabla o prosa con causa:

| Dimensión | EC2 (lo que lanzaste) | Lambda (hipótesis) |
| --- | --- | --- |
| Estado | Disco / proceso largo en la VM | Sin disco persistente de app; efímero por invocación |
| Duración | Horas/días si dejas la VM | Segundos/minutos por request (límites del servicio) |
| Puerto / listen | Proceso con `listen` 24/7 (SG, IP/ALB) | Handler sin `listen`; lo invoca un evento (p. ej. API Gateway) |
| Coste 24/7 | Pagas mientras la instancia está *running* | Pagas por invocación/tiempo de ejecución |

   Escribe 4–8 frases: ¿este lab encajaría en Lambda? ¿por qué sí/no? (estado, duración, puerto, factura).

8. **Terminate.** Selecciona la instancia → **Instance state** → **Terminate instance** (o el apagado que marque el lab). Espera *terminated* / lista vacía según corresponda.

9. **Evidencia de limpieza.** Captura la lista de instancias (vacía o *terminated*). Sin esto, la rúbrica de limpieza falla aunque el launch estuviera bien.

## Evidencia ↔ rúbrica

| Criterio | Qué dejar en el `.md` |
| --- | --- |
| Lab EC2/AMI | Región, AMI/tipo/SG; captura instancia *running* |
| Comparación Lambda | Tabla o prosa: estado, duración, puerto, coste 24/7 |
| Limpieza | Terminate + captura lista vacía / *terminated* |
| Claridad del `.md` | Sin quedarse solo en el logo; comparación explícita |

## Errores frecuentes

- Tipo grande «por si acaso» o SG abierto de más.
- Entregar solo el logo de EC2 sin el bloque comparación.
- Olvidar **terminate** y dejar la VM facturando.
- Confundir Spot (modelo de precio) con un tipo de instancia.
- Pegar claves `.pem` o capturas con secretos en el `.md`.

## Limpieza

*Terminate* instancias del lab; borra AMI/snapshots solo si el enunciado lo pide. Comprueba la lista de instancias. **End Lab** al cerrar.
